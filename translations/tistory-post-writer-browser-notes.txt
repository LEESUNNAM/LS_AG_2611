# tistory-post-writer 브라우저 메모

claude-in-chrome으로 Chrome을 조작하며 확인한 실무 내용입니다. 어떤 단계가 예상과 다르게 동작할 때 읽으세요.

## 조사 중 탐색

- Google News 검색 페이지는 헤드라인 목록을 보여주지만, 목록에 `get_page_text`를 써도 기사 URL은 나오지 않습니다. `find`나 `read_page`(interactive 필터)로 각 링크의 ref를 얻어 `left_click`합니다. 기사는 보통 새 탭에서 열리므로 `tabs_context_mcp`로 탭 ID를 받아 `get_page_text`로 읽습니다.
- Google News의 `./read/...` 링크로 바로 이동하면 잠깐 빈 페이지가 보일 수 있습니다. 3초 기다린 뒤 읽으세요. 탭의 URL이 실제 기사 URL로 바뀝니다.
- 아주 긴 페이지에서는 `get_page_text`가 50,000자에서 잘릴 수 있습니다. 필요한 부분은 한도 안에 있었지만 나머지를 읽지 못했다면 출처 목록에 일부만 읽었다고 적거나, `read_page`로 ref를 지정해 더 읽습니다.
- 일부 언론사는 "일시적으로 제한됨"이나 봇 확인 페이지를 보여주고, 확장 프로그램이 "이 도메인의 페이지 내용 읽기 권한 거부"를 알리기도 합니다. 둘 다 차단된 것으로 봅니다. 반복 재시도하지 말고, 우회하려 하지 말고, 그 출처를 버리고 다른 출처를 쓰세요. 읽지 못한 페이지는 인용하지 않습니다.
- 유료 구독 벽이 있거나 잘려 보이는 페이지(예: Barron's, 또는 "펼쳐서 계속 읽기" 뒤에 가려진 Fast Company)는 헤드라인과 몇 문단만 돌려줍니다. 어떤 페이지(한 번은 Motley Fool)는 제목만 돌려주기도 합니다. 이는 기껏해야 일부만 읽은 것입니다. 읽은 것으로 세지 말고, 본 텍스트에 없던 사실은 인용하지 마세요. 본 내용만 인용한다면 "(본문 일부만 열람)"이라고 표기합니다.
- 일부 도메인은 확장 프로그램 자체가 차단합니다("This site is blocked."). 그런 페이지의 탭은 `tabs_close_mcp`로도 닫히지 않을 수 있으니, 사용자에게 어느 탭을 직접 닫아야 하는지 알려주세요.
- 한 번의 실행에서 출처 8건 중 깔끔하게 열린 것은 2건뿐이었습니다. 필요한 수보다 많은 후보를 열어 두고, 전문을 읽은 출처가 5건 미만이면 글 본문과 마지막 보고에 분명히 밝히세요.
- 클릭하면 의도한 헤드라인과 다른 기사가 열릴 수 있습니다(관련 기사 목록이 바뀜). 결과 텍스트를 쓰기 전에 항상 제목과 URL을 확인하세요.
- 사이트가 콘텐츠를 그대로 옮기지 말라고 안내하면, 자신의 말로 요약하고 출처를 표기합니다.

## 티스토리 화면

- 로그인 확인: 홈 화면 상단에 "글쓰기" 링크가 있고, 계정 메뉴에 "로그아웃" 버튼이 있습니다. 로그아웃 상태에서는 둘 다 보이지 않으며, 대신 "시작하기" 버튼이 있어 누르면 "카카오계정으로 로그인" 창이 열립니다.
- "글쓰기"는 `https://<블로그>.tistory.com/manage/newpost`를 새 탭에서 엽니다.
- 편집기 구성(좁은 화면): 위쪽에 도구 모음, 그 아래 카테고리 선택, 제목 칸, 본문 영역이 있습니다. 화면 폭이 편집기보다 좁으면 일부 컨트롤이 화면 밖에 있으므로, 좌표를 추측하지 말고 `find`와 ref에 `scroll_to`를 쓰세요.
- 아래쪽 버튼: "미리보기", "맞춤법", "임시저장", "완료". 페이지는 자동 저장도 하며 "자동 저장 완료 HH:MM:SS" 문구가 나타납니다.
- 임시저장 확인: "임시저장"을 누르면 "작성 중인 글이 저장되었습니다." 배너가 뜨고 버튼에 개수("임시저장 개수 1개")가 표시됩니다. 이것을 임시저장이 되었다는 증거로 씁니다.
- 한 줄에 단독으로 입력한 URL은 편집기가 링크 미리보기 카드(제목, 설명, 도메인)로 바꿉니다. 해가 되지는 않으며 출처 목록이 풍부해 보이지만 세로 공간을 더 차지합니다.
- "완료"는 "공개", "공개(보호)", "비공개" 라디오 버튼과, 선택에 따라 이름이 바뀌는 아래 버튼("비공개 저장" 등)이 있는 발행 패널을 엽니다. 패널이 마지막 선택을 기억할 수 있으므로, 확정하기 전에 항상 스크린샷으로 선택된 옵션을 읽으세요.
- 아래 버튼을 누르면 DKAPTCHA 창(지도 이미지, 빈칸 글자 맞히기, "답변 제출")이 나타날 수 있습니다. 풀 수 있는 사람은 사용자뿐입니다.
- 발행에 성공하면 브라우저가 `<블로그>.tistory.com/manage/posts/`로 이동합니다. 목록에는 제목, 카테고리, 작성자, 날짜가 나오고, 비공개 글에는 "비공개" 표시가 붙습니다. 제목 링크의 href가 글 주소입니다. 예: `https://<블로그>.tistory.com/4`.

## 편집기에 입력하기

- 제목 칸을 클릭해 제목을 입력하고, 본문 영역을 클릭해 본문을 입력합니다. `type` 동작은 줄바꿈을 받습니다. 텍스트는 평범한 JSON 문자열로 전달하세요. 형식이 깨진 배치 호출(너무 긴 본문이 잘리거나 잘못 이스케이프된 경우)은 입력이 시작되기 전에 입력 검증 오류로 실패하므로, 깨끗한 호출로 다시 보내면 됩니다.
- 입력 직후 스크린샷에서는 편집기가 맨 아래로 스크롤되어 보일 수 있습니다. 글자가 들어갔는지 판단하기 전에 위로 스크롤하세요.
